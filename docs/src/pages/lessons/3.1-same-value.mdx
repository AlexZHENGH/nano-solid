在 [3.0](../3.0-effect-lifecycle/) 的演示里，把 `0` 再次写回当前已经是 `0` 的 signal，Console 没有任何动静。但按我们[第二章](../2.0-reactivity/)的写法，每次调用 `setCount(0)` 都会照常遍历 `subscribers`，把所有依赖它的 effect 白白再跑一遍。

## 为什么不用 `===` 而用 `Object.is`？

拦住无变化写入的思路很简单：在 `set(next)` 一开头比较新旧两个值，相同就直接 `return`，不更新也不通知。

直觉上可能会写 `if (value === next) return;`，但在 JavaScript 里，`===` 有两个边界容易踩坑：

1. **`NaN === NaN` 是 `false`**：如果一个计算结果算出了 `NaN`，之后再次写入 `NaN`，用 `===` 会永远认为“值变了”，反复触发下游重跑。
2. **`+0 === -0` 是 `true`**：在少数区分正负零的数值计算里，`===` 看不出两者的区别。

`Object.is(value, next)` 正好补齐这两处：`Object.is(NaN, NaN)` 返回 `true`，而 `Object.is(+0, -0)` 返回 `false`，其余情况和 `===` 完全一致。

> [!NOTE]
> 对于对象和数组，`Object.is` 比较的是引用地址而不是深层内容。原地修改数组后再把同一个数组传给 setter，引用没变就不会触发更新；要触发更新，需要传入新的对象或数组引用。

## 预期效果

点下面的 `写入相同值 setCount(0)`，代码框会追加一行 `setCount(0);`，但 Console 不会多出日志。接着点 `写入新值 setCount(1)`，Console 才会打印 `1`。
