勾选一条 Todo 时，复选框应当马上反映这次编辑。下面的“已完成明细”可以稍后整理。如果明细包含很多条任务，而你连续勾选了三项，前两次整理出来的内容很快就过时了。本节给这种工作一个可以排队、替换和取消的入口。

切到本课的练习快照后，运行 `pnpm dev`，在终端给出的地址后加上 `/examples/todo-app/async.html`。等列表加载完成，点“查看已完成明细”，再快速勾选或取消几项。列表和剩余数量会立刻更新，明细短暂显示“正在整理明细…”。示例每轮特意等约 800 毫秒，方便看清先后。调度器默认用 `setTimeout(run, 0)` 安排下一轮。

## 先排队，轮到时再挑一笔工作

`schedule(callback, options)` 把回调放进 `pending`，返回一个取消函数。调用时先把当前代码跑完，再让宿主执行排上的一轮。每轮只取一笔。取出后先删掉，再调用回调，这样回调也能用同一个键安排后续工作。

到轮次真正开始时再比优先级。比如明细早一步排进队列，但在这一轮开始前又安排了一笔处理交互的任务，先挑交互。优先级相同就沿用排队顺序。

| 优先级          | 可以放进去的工作                     |
| --------------- | ------------------------------------ |
| `user-blocking` | 下一轮需要尽快处理的交互工作         |
| `normal`        | 普通任务，省略优先级时使用           |
| `idle`          | 可以往后放的展示工作，例如已完成明细 |

这里的 `idle` 只是队列里最低的优先级。宿主没有保证浏览器正空闲，调度器也只能在回调开始前挑选任务。已经开始的同步回调会完整执行。

## 给重复工作一个共同的键

展开明细时先排一次整理。接下来每次勾选都想再排一次，但只要之前那笔还没开始，就可以用新任务替换它。用同一个 `key` 向 `Map` 写入会替换旧值，排队位置保持原样。没有传 `key` 的任务用独立的 `Symbol`，各自排队。

替换之后，旧调用返回的取消函数可能还在手里。只按键删除会误删新任务。让取消函数记住这次放进去的 `task`，等到 `pending.get(key) === task` 才删除，就能只取消自己的安排。

## 把计算留到明细任务里

看 `ScheduledCompletedDetails.tsx`。它在 `createEffect` 里读任务列表，用这一读跟踪何时需要更新。真正调用惰性的 `completedDetails` 是在排好的回调里。这样同一个键被替换三次，最后只整理一次最新列表。点“收起已完成明细”或“重新打开应用”时，`onCleanup` 会取消还没开始的整理。

在题目版中，明细已经能延后显示，但每次编辑还是单独排队。`src/scheduler.test.ts` 可以逐轮推进队列，直接断言执行顺序。明细组件的测试也会检查连续编辑后只发生一次计算。保存继续走上一节的 Store，由它负责等服务器确认整份快照。

> [!PRACTICE]
>
> ```sh
> git switch -c solve/12.4 12.4-learn
> ```
>
> 一轮优先执行等级最高的等待任务。同键替换只执行最新回调，旧取消函数不能删掉新安排。连续编辑只整理一次最新明细，关闭明细时取消待执行的整理。
>
> ```sh
> pnpm format && pnpm check && pnpm test:run
> ```
