在 [5.4](../5.4-components/) 结束时，我们已经能用函数组件拼出完整的计数器，并把启动入口收敛成一句 `render(<App />, app)`。但回头细看 `src/main.tsx`，仍有三个绕不开的痛点：

1. **条件切换还是手写命令式胶水**：为了在 `<Counter />` 和 `<EmptyState />` 之间切换，`App` 不得不手工建一个空的 `host` 节点，维护一个 `unmountActiveView` 变量，并在点击按钮时手动调 `unmountActiveView?.()` 再重新 `render`。
2. **组件内部副作用没法自动回收**：如果组件自己在函数体里启动了一个 `setInterval` 或写了一个 `createEffect`，它目前只能把资源暴露出来靠外层手工清理，框架本身不知道“这个副作用归哪个组件管”。
3. **兄弟节点中途抛错仍会泄漏**：在 [5.3](../5.3-reactive-props/) 留下的伏笔里，如果父元素下有两个兄弟 `<A /><B />`，`<A />` 刚建好后 `<B />` 抛错，代码还没走进父元素，`<A />` 建立的订阅和监听就无人回收。

这一章我们引入 SolidJS 最核心的生命周期抽象**所有权树（Ownership）**，把“清理谁、何时清理”彻底交给创建资源的作用域，再用声明式的 `<Show>` 取代手写切换逻辑：

```tsx
<Show when={visible} fallback={() => <EmptyState />}>
  {() => <LiveCounter onTick={recordTick} onDispose={recordCleanup} />}
</Show>
```

先体验一下这一章的终点效果：页面打开后，`<LiveCounter />` 内部启动了一个每秒触发一次的后台定时器，并在组件内用 `onCleanup` 登记了停止逻辑。点击 `隐藏计数器（触发 onCleanup）`，观察底部的 `后台定时器 tick` 立刻停住，`onCleanup 清理次数` 加一；再次点击 `重新显示计数器`，会挂载一份全新的局部计数并恢复计时：

这一章分四小节把所有权与条件渲染完整搭起来：

- **6.1 嵌套 effect 归谁清理**：把记录归属的 `currentOwner` 与追踪依赖的 `currentEffect` 分开，让外层 effect 重跑或释放时自动清理内层后代 effect。
- **6.2 `createRoot` 与 `onCleanup`**：提供可独立释放的根作用域与 LIFO 清理钩子，并在非追踪环境下安全执行清理、在构造抛错时自动回滚已登记资源。
- **6.3 原生节点与延迟挂载**：正式退掉 `Renderable`，让 DOM 与 JSX 直接返回原生 `Node`，将 `render` 升级为 `render(() => <App />, container)`，自动兜住兄弟节点抛错回滚。
- **6.4 条件渲染 `<Show>`**：用一对 `Comment` 锚点节点和懒分支工厂实现 `<Show>`，彻底删掉 `src/main.tsx` 里的手写 `host` 与切换句柄。
