`setCount` 只知道新值是多少，并没有直接调用打印函数。那打印函数是怎么知道自己该再跑一遍的？

这一章我们就亲手把这件事做出来。先用 `createSignal` 留住一个值，再用 `createEffect` 把“读过这个值”和“值变了就重跑”连起来。学完后，你写的框架就能在终端跑通下面这段代码，依次打印 `0`、`1`、`2`：

```ts
// 创建一份响应式状态：count 用来读取，setCount 用来更新。
const [count, setCount] = createSignal(0);

// 首次运行会打印 0，之后每次写入 count 都会自动重跑。
createEffect(() => console.log(count()));

setCount(1);
setCount(2);
```

整章分三小步推进：

- **[2.1 用闭包保存值](../2.1-signal/)**：实现最小版本的 `createSignal`，让写入真的改变后续读到的值。
- **2.2 写入时通知订阅者**：先手动登记回调，看清楚 setter 怎么通知关心它的函数。
- **2.3 让 effect 自动追踪依赖**：去掉手动登记，让 getter 在读值时自己记下正在运行的 effect。

上面的交互演示由真正的 SolidJS 驱动。做到 `2.3` 结束时，在本地跑 `pnpm dev`，你会用自己写的框架看到一模一样的结果。
